🚨 2. النواقص الحالية في المحرك

🔴 نقص حرج 1: SOROBAN_BANK فارغ

```typescript
// في adaptiveEngine.ts و problemGenerator.ts:
const SOROBAN_BANK: BankQuestion[] = [];  // ← فارغ!
```

التأثير: adaptiveEngine لا يستطيع اختيار أسئلة، و problemGenerator لا يستطيع توليدها.

الحل: ربطها بـ srb-adapter (getQuestionsByLevel, getQuestionsByModule, إلخ).

🔴 نقص حرج 2: evaluateBankAnswer وهمي

```typescript
function evaluateBankAnswer(_q, _a, _t) {
  return { correct: false, tooSlow: false, timeout: false, issue: "none" };
}
```

التأثير: adaptiveEngine لا يعرف هل إجابة الطالب صحيحة أم لا.

الحل: استبدالها بـ getDecimalFactor + مقارنة abacusValue (الموجودة في srb-adapter).

🔴 نقص حرج 3: الجلسة العلاجية تستخدم النتيجة النهائية فقط

```typescript
// في RemediationScreen.tsx:
const isCorrect = abacusValue === currentQ.result;  // ← النتيجة النهائية فقط
```

التأثير: الطفل يمكنه استخدام آلة حاسبة، أو التخمين، أو تحريك الخرزات عشوائياً.

الحل: التحقق من كل خطوة على المعداد (مثل LaserAbacus في الدوجو).

🟡 نقص 4: لا يوجد "توجيه خطوات" تفاعلي

الجلسة الحالية تعرض النتيجة الصحيحة فقط، ولا تعرض "كيف" يُحرّك الطفل الخرزات خطوة بخطوة.

الحل: استخدام sorobanEngine لتوليد الخطوات، وعرضها بالشكل الذي نراه في الدوجو (أشباح + أسهم + وميض أحمر).

🟡 نقص 5: لا يوجد جسر بين srb-adapter و sorobanEngine

adaptiveEngine يستخدم BankQuestion، و sorobanEngine يستخدم {operands, operation}. لا يوجد شيء يربطهما.

الحل: إنشاء questionTracer.ts الذي يأخذ SRBQuestion ويعيد SolveStep[].

🟡 نقص 6: لا يوجد منطق للكسور والجذور

sorobanEngine يعرف الجمع/الطرح فقط.

الحل:

· L6 (عشريات): sorobanEngine + factor + خطوة فاصلة.
· L7 (جذور): التحقق العكسي (traceMultiplication للتحقق).

🎨 5. تصميم الجلسة العلاجية بعد التطوير

المرحلة الحالية (بدون تطوير):

```text
سؤال → Soroban2D5 → "تحقق" → النتيجة النهائية فقط
```

المرحلة بعد التطوير (تعليم تكيفي):

```text
سؤال → questionTracer → خطوات (SolveStep[])
       ↓
   عرض الخطوة 1 → [Soroban2D5 + أشباح + تحقق خطوة بخطوة]
       ↓
   إذا أخطأ: وميض أحمر + إعادة
       ↓
   إذا صح: الخطوة 2 ... إلخ
       ↓
   النتيجة النهائية → تقييم (70% من الخطوات الصحيحة)
```

🎯 معايير النجاح الجديدة:

المعيار الوصف
النجاح 70% من الخطوات الصحيحة (وليس من الإجابات).
الفشل إذا لم يحقق 70% → يعيد الجلسة.
المساعدة بعد 3 محاولات فاشلة → عرض الحركة الصحيحة (يُحسب كصحيح).
الفخ الحالي التخلص من "الفشل" بناءً على النتيجة النهائية فقط.

المرحلة (ب) [اختيارية]: تغليف التطبيق (Capacitor) للنشر على المتاجر

🎯 الهدف

تحويل تطبيق الويب (PWA) إلى تطبيق أصلي (APK / AAB) يمكن رفعه على Google Play أو المتاجر البديلة (Amazon Appstore، Huawei AppGallery).

⚠️ القيود السورية (مهم جداً)

· Google Play Console: لا يزال مقيداً للمطورين السوريين.
· الإعفاء الجديد: يسمح فقط بالتوزيع المحلي (APK sideloading) وليس بالنشر الدولي عبر Google Play.
· الحل العملي: توزيع APK مباشرة عبر موقعك أو متاجر بديلة (Amazon، Huawei)، أو التعاون مع شريك خارج سوريا لفتح حساب Google Play.

📋 المتطلبات التقنية

1. @capacitor/core و @capacitor/cli: الحزم الأساسية.
2. Android Studio (لبناء APK) أو Xcode (لـ iOS).
3. حساب مطور (25$ لـ Google Play، أو حساب مجاني لـ Amazon/Huawei).

⚙️ خطوات التنفيذ (عملياً)

الخطوة 1: تثبيت Capacitor

```bash
npm install @capacitor/core @capacitor/cli
npx cap init
```

· سيُطلب منك: اسم التطبيق (SorobanMind)، ومعرّف الحزمة (com.mezo2021.sorobanmind).

الخطوة 2: إضافة منصة Android

```bash
npx cap add android
```

· سيتم إنشاء مجلد android/ تلقائياً.

الخطوة 3: نسخ الملفات المبنية

```bash
npm run build
npx cap copy
```

الخطوة 4: فتح Android Studio

```bash
npx cap open android
```

· سيُفتح Android Studio، ومنه يمكنك بناء APK أو AAB.

الخطوة 5: بناء APK / AAB

· من Android Studio: Build > Build Bundle(s) / APK(s) > Build APK(s).
· أو من سطر الأوامر: ./gradlew assembleRelease (داخل مجلد android/).

✅ النتيجة

· ملف APK: يمكن توزيعه مباشرة (sideloading) أو رفعه على متاجر بديلة.
· ملف AAB: يمكن رفعه على Google Play (إذا توفر حساب مطور).

🛡️ ملاحظة أمنية

· التطبيق سيستخدم نفس كود React (بدون تغيير).
· getSession و PWA سيعملان داخل التطبيق الأصلي أيضاً.
· Supabase: المزامنة السحابية ستعمل كما هي (الإنترنت مطلوب للمزامنة فقط).
