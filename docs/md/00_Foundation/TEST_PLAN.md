# SorobanMind-2 — Master Test Plan

**تاريخ الوثيقة:** 16 نوفمبر 2026
**المشروع:** SorobanMind-2
**الحالة:** خطة الاختبارات المعتمدة — التنفيذ لم يبدأ بعد
**المرجع:** UNIFIED_REFERENCE.md + MASTER_REMEDIATION_PLAN.md

---

## 1. الهدف

تحديد اختبارات الإصلاحات قبل تنفيذها، ومنع انتقال أي إصلاح إلى المرحلة التالية قبل اجتياز اختبارات البناء والاختبارات الوظيفية الخاصة به.

هذه الوثيقة تحدد:
- ما الذي يجب اختباره.
- النتيجة المتوقعة.
- حالات الفشل التي يجب منعها.
- شروط قبول الإصلاح.
- ترتيب الاختبارات بين المراحل.

**مهم:** وجود اختبار في هذه الوثيقة لا يعني أنه نُفّذ أو نجح.

---

## 2. قواعد الاختبار العامة

1. لا تستخدم حسابات المستخدم الحقيقية للاختبارات التخريبية.
2. استخدم حسابات اختبار منفصلة عند الحاجة إلى Supabase Auth.
3. لا تحذف بيانات المستخدم الحقيقية أثناء الاختبارات.
4. لا تنفذ SQL أثناء اختبارات الواجهة الأمامية.
5. لا تغيّر App.tsx أو storage.ts لمجرد تسهيل الاختبار.
6. اختبر Local وCloud كلٌّ على حدة عندما يكون ذلك مطلوباً.
7. اختبر حالات النجاح والفشل، وليس النجاح فقط.
8. بعد كل Commit نفّذ Build واختبارات الإصلاح المحدد.
9. عند فشل الاختبار، توقف وسجّل السبب قبل متابعة العمل.
10. لا تعتبر نجاح Build دليلاً كافياً على نجاح السلوك الوظيفي.

### تصنيف النتائج

- PASS: اجتاز الاختبار.
- FAIL: فشل الاختبار.
- BLOCKED: تعذر الاختبار بسبب نقص بيئة أو بيانات أو صلاحيات.
- NOT RUN: لم يُنفّذ بعد.
