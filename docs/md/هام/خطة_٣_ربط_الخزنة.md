**ب) الدالة.** استبدل `async function adoptUser(user: User): Promise<void> { ... }` كاملة (من سطرها الأول حتى القوس `}` الذي يسبق `async function restorePreviousSession(` مباشرة) بـ:

```ts
async function adoptUser(user: User): Promise<void> {
  requireCloudMode();

  // تعافٍ من انقطاع سابق أثناء تبديل حساب، قبل قراءة أي حالة
  try {
    recoverInterruptedSwitch(localStorage);
  } catch {
    throw new CloudSyncError(
      'Failed to recover interrupted account switch',
      'ADOPTION_FAILED',
    );
  }

  const owner = localStorage.getItem(OWNER_KEY);
  const slot = getActiveAccount(localStorage);
  // الخانة قد تخالف OWNER_KEY بعد انقطاع بين التبديل وكتابة المالك
  const different =
    !owner || owner !== user.id || (slot !== null && slot !== user.id);

  // لا ننقل اختياراً معلّقاً من حساب سحابي سابق إلى حساب آخر.
  const pendingAvatar =
    localStorage.getItem('soroban_avatar_pending_upload') === '1' &&
    (!owner || owner === user.id);

  const pendingHeroKey = pendingAvatar
    ? localStorage.getItem('soroban_hero_key')
    : null;

  // جلب بيانات الحساب قبل لمس الحالة المحلية.
  const { data: profile, error: profileError } = await supabase
    .from('public_profiles')
    .select('avatar_id')
    .eq('user_id', user.id)
    .maybeSingle();

  if (profileError) {
    throw new CloudSyncError(
      'Failed to fetch account profile',
      'PROFILE_FETCH_FAILED',
    );
  }

  const cloudProgress = different
    ? await pullProgress(user.id)
    : null;

  const cloudAvatarId: string | null = profile?.avatar_id ?? null;

  // Snapshot قبل أول تغيير محلي.
  const snapshot = createLocalStateSnapshot();
  let switched = false;
  let ownerBefore: string | null = null;

  try {
    if (different) {
      // جهاز قديم: الخانة غير مهيأة والمالك معروف ← ثبّت صاحب البيانات الحالية أولاً
      // حتى لا تُنسب بياناته إلى الحساب الجديد.
      if (getActiveAccount(localStorage) === null && owner) {
        switchAccount(localStorage, owner);
      }
      ownerBefore = getActiveAccount(localStorage);

      // التبديل متزامن بالكامل: لا await بين حفظ الحساب السابق واستعادة الجديد.
      switchAccount(localStorage, user.id);
      switched = true;

      // المتجر في الذاكرة ما زال يحمل بيانات الحساب السابق.
      // لا نستدعي reset() قبل القراءة لأنه يكتب فوق البيانات المستعادة.
      if (localStorage.getItem('cloud:sorobanmind-v2-progress') === null) {
        useProgressStore.getState().reset();
        if (cloudProgress) {
          useProgressStore.setState(cloudProgress);
        }
      } else {
        await useProgressStore.persist.rehydrate();
      }

      localStorage.removeItem('soroban_avatar_pending_upload');
      localStorage.removeItem('soroban_hero_key');
      localStorage.removeItem('soroban_child_name');

      // الاسم الكامل يخص الهوية السابقة: يُحذف عند تبديل حساب فعلي فقط
      // (ليس عند أول دخول، ولا عند الحساب نفسه).
      if (owner && owner !== user.id) {
        localStorage.removeItem('soroban_child_full_name');
      }
    }

    if (cloudAvatarId) {
      localStorage.setItem('soroban_hero_key', cloudAvatarId);
      localStorage.removeItem('soroban_avatar_pending_upload');
      applyLocalIdentity();
    } else if (pendingAvatar && pendingHeroKey) {
      localStorage.setItem('soroban_hero_key', pendingHeroKey);
      applyLocalIdentity();

      try {
        const { error: avatarError } = await supabase.rpc('set_my_avatar', {
          p_avatar_id: pendingHeroKey,
        });

        if (avatarError) {
          console.warn('تعذرت مزامنة شخصية البطل:', avatarError.message);
        } else {
          localStorage.removeItem('soroban_avatar_pending_upload');
        }
      } catch (err) {
        console.warn('خطأ في مزامنة شخصية البطل:', err);
      }
    } else {
      localStorage.removeItem('soroban_avatar_pending_upload');
      applyLocalIdentity();
    }

    // OWNER_KEY آخر خطوة بعد نجاح التغييرات المحلية.
    localStorage.setItem(OWNER_KEY, user.id);
  } catch (error) {
    try {
      // نعكس التبديل أولاً (الـSnapshot أدناه لا يغطي مفاتيح vault:)
      if (switched && ownerBefore) {
        switchAccount(localStorage, ownerBefore);
      }
      restoreLocalStateSnapshot(snapshot);
    } catch {
      throw new CloudSyncError(
        'Failed to restore previous local state',
        'SESSION_RESTORE_FAILED',
      );
    }

    if (error instanceof CloudSyncError) {
      throw error;
    }

    throw new CloudSyncError(
      'Account adoption failed',
      'ADOPTION_FAILED',
    );
  }

  if (different) {
    window.setTimeout(() => window.location.reload(), 1200);
  }
}
```

## الخطوة 3-3: بوابة `getSession` في `cloudSync.ts`

**المشكلة:** جلسة محفوظة لحساب B بينما بيانات الجهاز لحساب A (مثلاً بعد دخول من تبويب آخر) كانت تُعرض دون اعتماد.

**أ) الدالة المساعدة.** ضعها مباشرة **قبل** السطر `export const cloudSync = {`:
```ts
function sessionNeedsAdoption(userId: string): boolean {
  const owner = localStorage.getItem(OWNER_KEY);
  return owner !== userId || needsAdoption(localStorage, userId, owner);
}
```

**ب) `getSession`.** ابحث عن:
```ts
  async getSession() {
    const { data } = await supabase.auth.getSession();
    if (data.session) {
      applyLocalIdentity();
      void retryPendingAvatar();
    }
    return data.session;
  },
```
استبدله بـ:
```ts
  async getSession() {
    const { data } = await supabase.auth.getSession();
    if (data.session) {
      if (getMode() === 'cloud') {
        const user = data.session.user;
        if (sessionNeedsAdoption(user.id)) {
          let adopted = false;
          for (let i = 0; i < 6 && !adopted; i++) {
            try {
              await withAuthLock(() => adoptUser(user));
              adopted = true;
            } catch (e) {
              const busy = e instanceof CloudSyncError && e.code === 'AUTH_FLOW_BUSY';
              if (!busy) {
                console.error('[cloudSync] adopt on getSession failed:', e);
                return null; // لا نعرض بيانات حساب آخر
              }
              // عملية اعتماد أخرى جارية: انتظر ثم أعد الفحص
              await new Promise((resolve) => setTimeout(resolve, 400));
              if (!sessionNeedsAdoption(user.id)) adopted = true;
            }
          }
          if (!adopted) return null;
        }
      }
      applyLocalIdentity();
      void retryPendingAvatar();
    }
    return data.session;
  },
```
**تنبيه معروف:** إن كان المتصفح بلا Web Locks فإن `withAuthLock` يرمي `AUTH_FLOW_BUSY` دائماً، فتعيد هذه الدالة `null` في حالة الحاجة للاعتماد فقط. هذا المتصفح لا يستطيع تسجيل الدخول أصلاً اليوم (`loginParent` يستخدم القفل نفسه)، فلا تراجع هنا.
**تنبيه ثانٍ:** عند اعتماد حساب مختلف داخل `getSession` تُعاد تحميل الصفحة تلقائياً مرة واحدة بعد ثانية ونصف؛ بعدها لا حاجة للاعتماد فلا تتكرر.

## الخطوة 3-4: اجعل CI أخضر

ادفع التعديلات على نفس الفرع وانتظر CI.

| الفشل الظاهر | السبب المرجّح | الإجراء |
|---|---|---|
| اختبار «A ثم B ثم C ثم A» يُظهر مفاتيح متبقية في `watched` | مفتاح ليس ضمن قائمة الخزنة | اعرف المفتاح، تحقق بـ`grep` أن كوداً يكتبه مباشرة، ثم أضفه إلى `ACCOUNT_BOUND_DIRECT_KEYS` في `accountVault.ts` وأضف سطر اختبار في `tests/accountVault.test.ts`. إن لم يكتبه أحد فعدّل الاختبار بدل القائمة |
| `persist.rehydrate is not a function` | نسخة zustand أو شكل المتجر | أرسل سجل الخطأ كاملاً للأداة؛ الحل البديل: استبدل `await useProgressStore.persist.rehydrate();` بـ`window.location.reload()` مؤجلاً (يعتمد على إعادة التحميل الموجودة) |
| «فشل بعد اكتمال المبادلة» أحمر | عكس التبديل لم يحدث | تأكد أن سطر `switchAccount(localStorage, ownerBefore)` داخل `catch` قبل `restoreLocalStateSnapshot` |
| اختبار `getSession` أحمر | الدالة المساعدة أو الاستيراد ناقص | تأكد من `needsAdoption` في الاستيراد ومن وضع `sessionNeedsAdoption` قبل `export const cloudSync` |
| أخطاء TypeScript | نوع `setState` | استخدم نفس سطر `useProgressStore.setState(cloudProgress)` الموجود أصلاً (كما هو في الكود أعلاه) |

**قاعدة:** أصلح السبب المحدد فقط. لا تعدّل منطق `accountVault.ts` (التبديل/التعافي) ولا تحذف اختباراً ليصبح CI أخضر.

> **⛔ شرط التوقف:** إن بقي اختبار «A→B→C→A» أو «فشل بعد اكتمال المبادلة» أحمر بعد محاولتين، **لا تدمج.** أغلق الـPR دون دمج، وسيبقى التطبيق على حالته المستقرة بعد الملف 2.

## الخطوة 3-5: اختبار يدوي إلزامي قبل الدمج

يحتاج حسابين تجريبيين (وثالثاً إن أمكن) على الهاتف، **ليس حساباتك الحقيقية**. انشر الفرع كمعاينة أو ادمج ثم جرّب سريعاً قبل الاعتماد على التطبيق.

1. **خط الأساس:** دخول الحساب A ← خروج ← دخول الحساب B ← خروج. لا أخطاء.
2. A: أنجز درساً وغيّر الشخصية ← خروج.
3. B: ادخل. يجب ألا يظهر شيء من A. أنجز درساً مختلفاً ← خروج.
4. C (إن وُجد): نفس الاختبار.
5. عد إلى A: يظهر درس A وشخصيته فقط. ثم B ثم C بالطريقة نفسها.
6. أغلق التطبيق بقوة (من قائمة التطبيقات) في منتصف تبديل حساب ثم افتحه: لا فقد ولا خلط.
7. تأكد أن PIN ولي الأمر والثيم واللغة لم تتغير بين الحسابات (هي بيانات جهاز).

**نجح؟** ادمج. **فشل أي بند؟** `git revert` للـPR (أو لا تدمجه)، ويبقى التطبيق على حالة الملف 2.
