A.2 ما هو منفذ بالفعل؟

Account Vault

4. تعليمات التعديل الدقيقة

أولاً: cloudSync.ts

أ) تعديل withAuthLock

الموضع الحالي:

authFlowInProgress = true;

try {
  return await navigator.locks.request(
    AUTH_LOCK_NAME,
    async () => task(),
  );
} finally {
  authFlowInProgress = false;
}

أضف إبطال مؤقتات Auto-Sync والعمليات القديمة بعد تعيين "authFlowInProgress = true".

بعد تحرير القفل، لا تعاود الجدولة إلا إذا:

- لم يعد هناك تعليق للمزامنة.
- انتهت الحاجة إلى التحقق من الجلسة.
- لا توجد عملية مصادقة جارية.
- توجد تغييرات محلية لم يتم رفعها.

استخدم "scheduleAutoSync(0)" عند تحقق هذه الشروط.

لا تغير اسم القفل.

ب) إضافة فحص ملكية الحساب

أضف الدالة التالية بعد دوال التحقق من وضع Cloud وملكية الحساب، وقبل بداية دوال رفع التقدم:

function isCurrentVaultOwner(userId: string): boolean {
  try {
    const owner = localStorage.getItem(OWNER_KEY);
    const active = getActiveAccount(localStorage);

    return owner === userId &&
      !needsAdoption(localStorage, userId, owner) &&
      (active === userId || active === null);
  } catch {
    return false;
  }
}

ملاحظة مهمة:

قبول "active === null" مسموح فقط كتوافق مع الأجهزة القديمة التي تعتمد "OWNER_KEY"، بشرط أن تكون "needsAdoption()" قد أكدت عدم وجود معاملة معلقة.

لا تستبدل هذا الفحص بمجرد وجود جلسة Supabase.

ج) الحفاظ على adoptUser

الموضع الحالي:

async function adoptUser(user: User): Promise<void> {

يُسمح بتغيير اسم الدالة إلى:

async function adoptUserCore(user: User): Promise<void> {

لكن يجب الحفاظ على جسم الدالة الأصلي دون إعادة تصميمه.

بعد نهاية "adoptUserCore()" أضف غلافاً خارجياً يتولى:

1. تعليق Auto-Sync بسبب "account-adoption".
2. تنفيذ "adoptUserCore()".
3. التحقق من هوية الحساب بعد الاعتماد.
4. تحديث حالة التحقق.
5. تحرير تعليق Auto-Sync في "finally".

لا تنقل "switchAccount()" أو "recoverInterruptedSwitch()" إلى موضع آخر.

لا تغيّر ترتيب عمليات Snapshot وRollback وكتابة "OWNER_KEY".

د) إضافة محرك Auto-Sync

أضف محرك المزامنة قبل:

async function restorePreviousSession(

يجب أن يحتوي على العناصر التالية:

- "SyncState"
- "SyncSuspensionReason"
- "syncSuspensions"
- "syncGeneration"
- "authGeneration"
- "dirtyVersion"
- "uploadedVersion"
- "syncPromise"
- "inFlightController"
- "authValidationRequired"
- "lastValidatedUserId"

ثم أضف الدوال:

suspendAutoSync()
markAuthTransition()
markAuthSessionValidated()
isSyncEligible()
withSharedAuthLock()
uploadCurrentProgressLocked()

استخدم تصميم الـ Patch الموجود "P3-00-Auto-Sync.patch" مرجعاً تنفيذياً لهذه الإضافات، مع التصحيحات الواردة في هذه الوثيقة.

هـ) قواعد Snapshot

داخل:

progressTriggerSnapshot()

استبعد من محفز الرفع:

language
soundEnabled
voiceEnabled
hapticsEnabled

لكن لا تحذفها من نتيجة:

extractPureState()

ولا من "progress_data".

و) قواعد الرفع

داخل "uploadCurrentProgressLocked()":

1. تحقق من Cloud Mode.
2. تحقق من المستخدم بواسطة "supabase.auth.getUser()".
3. تحقق من "OWNER_KEY".
4. تحقق من الحساب النشط.
5. تحقق من عدم وجود Adoption أو معاملة معلقة.
6. تحقق من "authGeneration" و"syncGeneration".
7. أعد التحقق من UID مباشرة قبل الإرسال.
8. التقط أحدث حالة تقدم.
9. نفّذ "upsert()" باستخدام نفس Payload الحالي.

لا تضف حقولاً إلى Payload.

استخدم:

.abortSignal(controller.signal)

لكن لا تعتبر AbortController ضماناً لمنع وصول طلب أُرسل بالفعل. الحماية الحقيقية هي القفل المشترك والتحقق من الهوية والجيل قبل الإرسال.

ز) القفل المشترك

"withSharedAuthLock()" يجب أن يستخدم:

AUTH_LOCK_NAME

نفسه.

لا تستدعِ "withAuthLock()" من داخل "withAuthLock()".

ولا تجعل "withSharedAuthLock()" يستدعي "withAuthLock()" داخلياً؛ كلاهما يستخدم قفل Web Locks نفسه بصورة مباشرة.

ح) عمليات الاستعادة والمصادقة

داخل "restorePreviousSession()" أضف تحديث حالة التحقق بعد استعادة الجلسة بنجاح.

داخل "getSession()":

- عند عدم وجود جلسة، سجّل حالة عدم وجود مستخدم.
- عند وجود جلسة، لا تعتبر "SIGNED_IN" وحده إثباتاً لملكية البيانات.
- لا تعلن صلاحية المزامنة إلا بعد اكتمال فحص الملكية.

داخل مستمع:

supabase.auth.onAuthStateChange()

استخدم عمليات تغيير الحالة المتزامنة فقط.

ممنوع تنفيذ عمليات Supabase غير متزامنة داخل Callback.

ط) saveToCloud()

استبدل التنفيذ الحالي بحيث يستخدم:

withSharedAuthLock()
uploadCurrentProgressLocked()

مع الاحتفاظ بإمكانية الحفظ اليدوي.

إذا بدأ الحفظ اليدوي أثناء Auto-Sync:

- لا تسمح بعمليتي Upsert متداخلتين.
- أوقف المؤقت القديم.
- ألغِ الطلب القديم بأفضل جهد.
- انتظر تحرير القفل.
- احفظ أحدث حالة.

ي) loadFromCloud()

استبدل جسم الدالة باستخدام:

- "suspendAutoSync('cloud-load')"
- "withSharedAuthLock()"
- التحقق من المستخدم والملكية قبل التطبيق.
- التحقق مرة أخرى بعد عمليات الجلب وقبل "beforeApply".
- تطبيق التقدم كما هو حالياً.
- تحديث "uploadedVersion" بعد نجاح الاستعادة.
- تحرير التعليق في "finally".

أبقِ Snapshot وRollback الموجودين في "GuardianDashboard.tsx".

ك) logoutParent()

يجب الحفاظ على التسلسل:

1. "saveToCloud()".
