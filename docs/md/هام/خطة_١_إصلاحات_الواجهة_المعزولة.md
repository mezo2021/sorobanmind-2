# الملف 1 من 3 — إصلاحات الواجهة المعزولة

**هدف هذا الملف:** خمس خطوات صغيرة مستقلة، كل واحدة PR مستقل. بعد إنهائه يكون التطبيق أكثر أماناً دون أن نلمس الخزنة أو التخزين.
**لا تبدأ الملف 2 قبل إنهاء كل خطوات هذا الملف وخضرة CI على main.**
**الملف مكتفٍ بذاته:** كل تعديل مكتوب بصيغة «ابحث عن هذا النص ← استبدله بهذا».

## قبل أن تبدأ (مرة واحدة)

1. على GitHub أنشئ وسماً (Tag) على main باسم `pre-final` (نقطة رجوع).
2. لكل خطوة: فرع جديد ← عدّل ← PR ← انتظر CI أخضر ← ادمج.
3. إن فشل CI: أصلح السبب فقط، ولا تنتقل للخطوة التالية.

## كيف تستخدم DeepSeek أو Gemini مع هذا الملف

- أعطه **خطوة واحدة فقط** في كل مرة، وليس الملف كله.
- هو لا يرى مستودعك. ألصق له الملف أو الدالة المعنية من GitHub، واطلب منه أن يعيدها كاملة بعد التعديل، ثم الصقها مكان القديمة.
- لا تقبل منه أرقام أسطر؛ اعتمد على النص المكتوب هنا فقط.

**القالب (ألصقه قبل كل خطوة):**

```
أنت تساعدني في مشروع React + TypeScript اسمه SorobanMind-2، وأعمل من هاتف.
نفّذ الخطوة التالية فقط ولا شيء غيرها.
ممنوع: تعديل أي ملف لم أذكره، حذف أي بيانات أو مفاتيح تخزين، إعادة كتابة ملف كامل، إضافة مكتبات.
سأعطيك النص الحالي للملف. إن لم تجد «النص القديم» المذكور في الخطوة حرفياً فتوقف وأخبرني ولا تخمّن.
أعد لي الجزء المعدّل فقط (الدالة أو الكتلة)، ثم اذكر ما تغيّر في سطر واحد.

```

## الخطوة 1-1: النشر لا يتم قبل نجاح الاختبارات (CI)

**المشكلة:** `deploy.yml` يبني وينشر دون تشغيل الاختبارات. و`ci-build.yml` يعمل على PR فقط.

**ملف 1:** `.github/workflows/deploy.yml`
ابحث عن:
```yaml
      - name: Install dependencies
        run: npm install --no-audit --no-fund

      - name: Build
        run: npm run build
```
استبدله بـ:
```yaml
      - name: Install dependencies
        run: npm install --no-audit --no-fund

      - name: Tests
        run: npm run test:run

      - name: Build
        run: npm run build
```
(لا تغيّر `npm install` إلى `npm ci` الآن؛ خارج النطاق.)

**ملف 2:** `.github/workflows/ci-build.yml`
ابحث عن:
```yaml
on:
  pull_request:
  workflow_dispatch:
```
استبدله بـ:
```yaml
on:
  push:
    branches:
      - main
  pull_request:
  workflow_dispatch:
```

**اختبار النجاح:** بعد الدمج يظهر في تشغيل Deploy خطوة Tests خضراء قبل Build.
**Commit:** `ci: run tests before deploy and on push to main`

```ts
  async function handleRecovery() {
    if (busy || isLocked() || recoveringRef.current) return;
    const value = recoveryInput.trim();
    if (!/^\d{8}$/.test(value)) {
      setError(t('أدخل رمزًا مكونًا من 8 أرقام.', 'Enter an 8-digit code.'));
      return;
    }
    recoveringRef.current = true;
    setBusy(true);
    try {
      const viaEmergency = value === EMERGENCY_CODE;
      let authorized = viaEmergency;
      if (!authorized) {
        const salt = localStorage.getItem(KEYS.recoverySalt);
        const savedHash = localStorage.getItem(KEYS.recoveryHash);
        if (salt && savedHash) {
          const candidate = await hashValue(value, salt);
          authorized = candidate === savedHash;
        }
      }
      if (!authorized) {
        setRecoveryInput('');
        registerRecFailure();
        return;
      }

      let warning = '';
      if (viaEmergency) {
        // نسجّل آخر استخدام فقط (لا الرمز ولا المُدخل)؛ فشل التسجيل لا يمنع الاسترداد
        try {
          localStorage.setItem(KEYS.emergencyUsedAt, new Date().toISOString());
        } catch {
          warning = t('تعذر تسجيل وقت استخدام رمز الطوارئ.', 'Could not record the emergency code usage time.');
        }
      } else {
        // الرمز العشوائي أحادي الاستخدام: نبطله ونتحقق قبل المتابعة
        localStorage.removeItem(KEYS.recoveryHash);
        localStorage.removeItem(KEYS.recoverySalt);
        if (
          localStorage.getItem(KEYS.recoveryHash) !== null ||
          localStorage.getItem(KEYS.recoverySalt) !== null
        ) {
          setError(t('تعذر إبطال رمز الاسترداد. لم يتم تغيير PIN.', 'Could not invalidate the recovery code. PIN was not changed.'));
          return;
        }
      }

      clearAllFailures();
      setRecoveryInput('');
      setPin('');
      setFirstPin('');
      setError(warning);
      setMode('newPin');
    } catch {
      setError(t('تعذر التحقق من رمز الاسترداد.', 'Recovery verification failed.'));
    } finally {
      recoveringRef.current = false;
      setBusy(false);
    }
  }
```
(إن لم تجد `hashValue` أو `registerRecFailure` فهي موجودة أصلاً في الملف؛ لا تعرّفها من جديد.)

**اختبار النجاح:** CI أخضر. يدوياً: استرد بالرمز العشوائي مرة ← ينجح؛ ثم حاول بنفس الرمز ← يفشل. رمز الطوارئ يعمل دائماً. PIN القديم يبقى صالحاً إن أغلقت التطبيق قبل حفظ PIN الجديد.
**ملاحظة:** عرض «آخر استخدام» داخل لوحة ولي الأمر مؤجل عمداً (لا قسم أمان فيها بعد)؛ التسجيل يعمل وحده.

## الخطوة 1-5: حفظ PIN الجديد قد يترك PIN تالفاً (بعد دمج 1-4)

**المشكلة:** `saveNewPin` يكتب أربعة مفاتيح بالتتابع دون Snapshot؛ فشل في المنتصف يترك هاشاً جديداً بملح قديم.

**أ)** ابحث عن هذه الأسطر الأربعة داخل `saveNewPin`:
```ts

    localStorage.setItem(KEYS.pinSalt, pinData.salt);
    localStorage.setItem(KEYS.recoveryHash, recoveryData.hash);
    localStorage.setItem(KEYS.recoverySalt, recoveryData.salt);
```
استبدلها بـ:
```ts
    const writes: Array<[string, string]> = [
      [KEYS.pinSalt, pinData.salt],
      [KEYS.pinHash, pinData.hash],
      [KEYS.recoverySalt, recoveryData.salt],
      [KEYS.recoveryHash, recoveryData.hash],
    ];
    // لقطة قبل الكتابة. بعد الخطوة 1-4 يكون رمز الاسترداد المستهلك null فلا يُعاد تفعيله
    const prev = writes.map(([k]) => [k, localStorage.getItem(k)] as [string, string | null]);
    try {
      for (const [k, v] of writes) localStorage.setItem(k, v);
      for (const [k, v] of writes) {
        if (localStorage.getItem(k) !== v) throw new Error('verify');
      }
    } catch {
      let rolledBack = true;
      try {
        for (const [k, v] of prev) {
          if (v === null) localStorage.removeItem(k);
          else localStorage.setItem(k, v);
        }
        for (const [k, v] of prev) {
          if (localStorage.getItem(k) !== v) rolledBack = false;
        }
      } catch {
        rolledBack = false;
      }
      throw new Error(rolledBack ? 'PIN_SAVE_FAILED' : 'PIN_SAVE_FAILED_UNCERTAIN');
    }
```
