# 1 --- الخزنة وعزل الحسابات

**المشروع:** SorobanMind-2\
**الهدف:** إنهاء عزل بيانات حسابات Cloud قبل الانتقال إلى المرحلة 2.\
**قاعدة التنفيذ:** بطاقة واحدة لكل PR. لا دمج مباشر إلى `main`. لا تنتقل
إلى البطاقة التالية قبل نجاح CI ومراجعة `diff`.

## قواعد إلزامية للمساعد المنفّذ

1.  اقرأ الملف المستهدف كاملاً قبل اقتراح التعديل.
2.  طابق النص القديم حرفياً مع فرع GitHub الحالي. إذا لم تجده، **توقف**
    ولا تخمّن موضعاً بديلاً.
3.  لا تعدّل إلا الملفات المحددة في البطاقة.
4.  لا تغيّر SQL أو `App.tsx` أو `src/utils/storage.ts` أو
    `src/store/progressStore.ts`.
5.  لا تعِد تصميم `src/utils/accountVault.ts`؛ هو المحرك المعتمد لهذه
    المرحلة.
6.  لا تحذف أو تنقل بيانات التخزين القديمة. المفاتيح القديمة غير المرحّلة
    تُترك كما هي.
7.  لا تعتبر CI الأخضر دليلاً على نجاح التبديل الفعلي بين الحسابات؛ بوابة
    M1/M2 اليدوية إلزامية.
8.  عند فشل CI، أصلح سبب الفشل فقط. لا توسّع نطاق البطاقة.
9.  لا تنشر بيانات أو كلمات مرور أو مفاتيح Supabase في المحادثة أو PR.

## ملاحظة تدقيق قبل التنفيذ

قائمة `ACCOUNT_BOUND_DIRECT_KEYS` في `accountVault.ts` موصوفة في الكود
الحالي بأنها **مؤقتة وتحتاج مطابقة شاملة**. لذلك لا يجوز الجزم بأن
المفتاحين المذكورين أدناه هما المفتاحان الوحيدان قبل جرد جميع استعمالات
`localStorage.getItem/setItem/removeItem` ومقارنتها بمحوّل `storage`. يجب
أن ينتهي هذا الجرد بتصنيف مكتوب: account-bound / device-only /
mode-prefixed / legacy-out-of-scope. لا تضف مفاتيح تخمينية.

## 1.6 --- اختبار تكاملي لتبديل الحسابات

**الملف الجديد:** `tests/cloudSync.vault.test.ts`

انسخ اختبار التكامل، لكن صحّح صياغة مفاتيح الخزنة إلى template literals
صحيحة. الصياغة التالية غير صالحة في TypeScript:

``` ts
ls.getItem(vault:account:${A})
```

والصحيح:

``` ts
ls.getItem(`vault:account:${A}`)
```

طبّق التصحيح نفسه على جميع مواضع `vault:account:${A}` و`${B}` و`${C}`.

يجب أن يغطي الاختبار: - A → B → C → A → B → C. - عدم تغيير البيانات عند
المالك نفسه. - فشل التبديل بعد اكتماله والتراجع العكسي. - بوابة
`getSession` قبل إرجاع جلسة حساب مختلف. - بقاء PIN والثيم واللغة ومفاتيح
الجهاز خارج الخزنة. - التقدم الرئيسي `cloud:sorobanmind-v2-progress`. -
مفاتيح persisted الأخرى، ومنها `cloud:soroban_mastery_badges`. - حالة
`owner = null`، وحالة slot مفقود مع Vault موجود: يجب ألا يحدث overwrite
صامت.

لا تدّعِ أن الاختبار يثبت واجهة المستخدم أو كل مخازن الذاكرة؛ هذه تُختبر في
M2.
