3. القرارات المعمارية الملزمة لمسار Cloud

هذه القرارات لا يجوز تغييرها أثناء التنفيذ دون مناقشتها والحصول على موافقة المستخدم:

1. كل حساب Cloud يمتلك بياناته المستقلة المرتبطة بهويته "user.id / UID".
2. بيانات الحساب A لا يجوز أن تظهر في الحساب B.
3. الانتقال A → B → C → A يجب أن يعيد بيانات كل حساب كما كانت.
4. لا يجوز حذف بيانات أي حساب Cloud عند تسجيل الخروج أو تبديل الحساب.
5. بيانات الجهاز تبقى على الجهاز، ولا تنتقل بين خزائن الحسابات.
6. PIN ولي الأمر والثيم وتفضيلات الجهاز والاسم الحقيقي ليست بيانات تُنقل تلقائياً بين الحسابات.
7. لا ترحيل تلقائي للبيانات القديمة.
8. لا حذف للبيانات القديمة أو مفاتيح الأرشيف لمعالجة أخطاء العزل.
9. لا SQL أو تغييرات Supabase دون موافقة صريحة.
10. لا يُعتبر نجاح Build دليلاً على سلامة انتقال البيانات.

المسار B — عزل الحسابات وCloud Account Vault

هذا هو المسار النشط حالياً، وهو الأولوية الحالية.

الهدف: معالجة جذور اختلاط البيانات وفقدانها عند الانتقال بين الحسابات، وليس مجرد تبديل بادئات التخزين.

ترتيب العمل المعتمد:

1. بناء "accountVault.ts" واختباره مستقلاً.
2. ربط المحرك بـ "cloudSync.ts" و"adoptUser()"، ومراجعة دور "wipeLocalProgress()" لمنع أي حذف لبيانات الحسابات.
3. بناء حاجز انتقال شامل يمنع الكتابة أثناء تغيير ملكية البيانات (Account Transition Barrier).
4. مراجعة النسخ الاحتياطي والتصفير والاستعادة، مع الحفاظ على حدود الملكية وقائمة المفاتيح المسموح بها.
5. اختبار الانتقال A → B → C → A، والانقطاع أثناء الانتقال، وفشل الاستعادة.
6. توثيق النتائج وإغلاق المرحلة بأدلة فعلية.

6. حالة الملفات الحالية المعروفة

"src/utils/storage.ts"

المستخدم أكد أن الملف لم يتغير عن النسخة الموجودة في الأرشيف.

الوظيفة الحالية:

- يقرأ وضع التطبيق بواسطة "getMode()".
- يضيف بادئة "local:" أو "cloud:" للمفاتيح.
- يوفر "getItem" و"setItem" و"removeItem".
- لا يوفر "clear" أو "key" أو "length".
- عند عدم وجود وضع، لا تتم القراءة أو الكتابة بصورة عادية.

"src/lib/cloudSync.ts"

المستخدم أكد أن الملف لم يتغير عن النسخة الموجودة في الأرشيف.

الآليات الموجودة في النسخة التي راجعناها:

- "createLocalStateSnapshot()"
- "restoreLocalStateSnapshot()"
- "wipeLocalProgress()"
- "adoptUser()"
- "loginParent()"
- "verifyOtp()"
- "logoutParent()"

يوجد حالياً أسلوب سابق لإدارة انتقال الحساب يعتمد على Snapshot وWipe وAdopt.

يجب دراسة علاقته بمحرك Account Vault قبل تعديل أي استدعاء.

لا نحذف "adoptUser()" أو "wipeLocalProgress()" لمجرد وجود المحرك الجديد.
