## P2-03 — عزل srb_progress ونقل البيانات القديمة بأمان
**التصنيف:** P2 | **الحالة:** ✅ مغلق تصميمياً (16 نوفمبر 2026)
**النطاق:** `src/data/srb/progress.ts` + `src/main.tsx` فقط

---

### 1. المشكلة الحالية

| الجانب | المشكلة |
|--------|---------|
| العزل | `srb_progress` مفتاح مشترك بين Local/Cloud، بلا بادئة |
| القراءة | `loadAllProgress()` تعيد `{}` عند أي فشل (قراءة، JSON، بيانات تالفة) → تُخفي الخطأ |
| الكتابة | `saveLevelGrade()` و `clearLevelProgress()` تبتلعان الأخطاء → حفظ وهمي |
| Migration | لا توجد آلية لنقل البيانات القديمة، ولا علم يمنع التكرار |
| الحذف | `clearAllProgress()` يحذف المفتاح الأصلي دون حماية من حذف أرشيف |

---

### 2. السلوك المستهدف (بعد P2-03)

#### 2.1 المفاتيح

| الغرض | المفتاح |
|-------|---------|
| Local | `local:srb_progress` |
| Cloud | `cloud:srb_progress` |
| علم Migration | `soroban_srb_migrated = "1"` |
| المصدر القديم | `srb_progress` (يُنقل ثم يُحذف) |

#### 2.2 معرفة الوضع

`progress.ts` تستورد `getMode()` من `src/utils/appMode.ts`.

- إذا أعادت `null` (وضع غير محدد / فشل قراءة): ترمي `SRB_MODE_UNAVAILABLE`. **لا تفترض Local.**
- لا تبعية دائرية (مؤكد).

#### 2.3 سلوك `loadAllProgress()`

| الحالة | الإرجاع | الكتابة/الحذف |
|--------|---------|----------------|
| Migration ناجح | `LevelProgressMap` طبيعي | مسموحة |
| Migration Blocked (فشل Quota + مصدر سليم) | بيانات المصدر القديم (قراءة مؤقتة فقط) | **محظورة** |
| Conflict (المصدر + الوجهة مختلفان) | `throw SRB_MIGRATION_CONFLICT` | محظورة |
| Corrupted (بيانات تالفة) | `throw SRB_PROGRESS_CORRUPTED` | محظورة |
| ModeUnavailable | `throw SRB_MODE_UNAVAILABLE` | محظورة |

**قاعدة صارمة:** لا `{}` عند أي فشل. لا بيانات فارغة مضللة.

#### 2.4 دالة مساعدة

`getSrbMigrationState(): 'ok' | 'blocked' | 'conflict' | 'corrupted' | 'mode-unavailable'`

- تُنفذ فحص Migration أو تحدّث الحالة قبل الإرجاع.
- لا تعيد `ok` لمجرد أن آخر محاولة كانت ناجحة.

#### 2.5 عمليات الكتابة والحذف

`saveLevelGrade` / `clearLevelProgress` / `clearAllProgress`:

- إذا `getSrbMigrationState() !== 'ok'`: **return early** (لا throw، لا كتابة، لا crash).
- هذا يحمي البيانات القديمة من الكتابة فوقها.

### 3. استراتيجية Migration

**مكان التنفيذ:** دالة داخلية `ensureSrbProgressMigration()` تُستدعى في بداية `loadAllProgress()`.

**ترتيب الخطوات:**

1. قراءة `soroban_srb_migrated`. إذا `"1"` → انتهى.
2. قراءة المصدر (`srb_progress`) والوجهة (`local:srb_progress`).
3. تحديد الحالة:
   - لا مصدر ولا وجهة → Migration اكتمل (لا شيء للنقل).
   - مصدر فقط → نسخ.
   - وجهة فقط → لا استبدال، Migration اكتمل.
   - كلاهما → قارن:
     - متطابقان → Migration اكتمل.
     - مختلفان → **Conflict** (لا استبدال تلقائي).
4. نسخ المصدر إلى `local:srb_progress` كما هو (بلا إعادة تشكيل).
5. إعادة قراءة الوجهة والتحقق من التطابق.
6. كتابة `soroban_srb_migrated = "1"` والتحقق.
7. حذف المصدر القديم **أخيراً**.

**قاعدة ذهبية:** المصدر لا يُحذف قبل نجاح 4+5+6 معاً.

---

### 4. QuotaExceeded — السلوك المعتمد

عند فشل النسخ (مساحة ممتلئة):

- المصدر يبقى كما هو.
- لا يُكتب العلم.
- **لا يُحذف المصدر.**
- `loadAllProgress()` تعيد البيانات القديمة (قراءة فقط).
- **كل عمليات الكتابة والحذف محظورة** حتى ينجح النقل.
- عند توفر مساحة: تُعاد المحاولة تلقائياً، ويُرفع الحظر بعد النجاح.

**قاعدة صارمة:** منع الكتابة يشمل **كل مسارات تعديل تقدم SRB**، وليس `saveLevelGrade` فقط. (يشمل `clearLevelProgress` و `clearAllProgress`).

### 6. القيود المعروفة (Known Limitations)

#### 6.1 ErrorBoundary لا يلتقط كل الأخطاء

React `ErrorBoundary` (في `main.tsx`) يلتقط الأخطاء **أثناء render فقط**. **لا يلتقط:**
- الأخطاء في `onClick` / `onSubmit`.
- الأخطاء في `useEffect`.
- الأخطاء في `async/await` (Uncaught Promise Rejection).

**النتيجة:** إذا استدعى مستهلك `loadAllProgress()` في `onClick` أو `useEffect` وأُطلقت حالة Conflict/Corrupted/ModeUnavailable:
- الطفل يرى **شاشة عالقة** (لا crash، لا رسالة).
- Console يعرض الخطأ.
- لا يمكنه المتابعة.

#### 6.2 UX مؤجل — P3-04

**P3-04 — SRB Migration Failure UX** (Backlog):

- إظهار حالة `blocked` / `conflict` / `corrupted` / `mode-unavailable` للمستخدم.
- توضيح سبب عدم ظهور التقدم أو تعذّر الحفظ.
- توفير مسار معالجة (Retry / Contact Support / Export Data) دون المخاطرة بالبيانات القديمة.

**القرار الواعي:** في Phase 2، نقبل قصور UX (silent failure في `onClick`/`useEffect` + شاشة عالقة نادراً) مقابل **ضمان سلامة البيانات الآن**.

### 7. الاختبارات (C21-C37)

| الاختبار | السيناريو | النتيجة المطلوبة |
|---------|-----------|------------------|
| C21 | Migration أساسي | نقل إلى `local:srb_progress` + حذف المصدر |
| C22 | Idempotency | لا تكرار للنقل عند القراءة المتعددة |
| C23 | Source Cleanup | حذف المصدر بعد نجاح الوجهة والعلم |
| C24 | Destination Write Failure | بقاء المصدر + عدم كتابة العلم + تفعيل الحظر |
| C25 | Verification Failure | عدم اعتماد الوجهة + عدم حذف المصدر |
| C26 | Flag Write Failure | بقاء المصدر + عدم اعتماد Migration |
| C27 | Source Removal Failure | Migration مكتمل + المصدر يبقى كنسخة زائدة |
| C28 | QuotaExceeded Read | قراءة المصدر القديم (قراءة فقط) |
| C29 | QuotaExceeded Write Block | رفض الكتابة + المصدر سليم |
| C30 | Retry After Quota Recovery | نجاح Migration بعد تحرير مساحة |
| C31 | Local/Cloud Isolation | كل وضع يقرأ بياناته فقط |
| C32 | Mode Switch Preservation | تقدم الوضعين مستقل |
| C33 | Clear Scope | حذف مساحة الوضع الحالي فقط |
| C34 | Consumer Compatibility | Practice/Anzan/Audio/LevelTest/Remediation تعمل |
| C35 | Existing Destination Conflict | توقف Migration + الاحتفاظ بالنسختين |
| C36 | Corrupted Legacy Data | توقف + الاحتفاظ بالمصدر |
| C37 | Interrupted Migration Recovery | استئناف آمن بعد الانقطاع |
