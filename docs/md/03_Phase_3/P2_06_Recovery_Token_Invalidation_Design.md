# P2-06 — إبطال Recovery PIN وتسجيل استخدام الطوارئ

> **الحالة:** ✅ مغلق تصميمياً
> **النطاق:** ملفان — `src/components/LocalPinGuard.tsx` + `src/screens/GuardianDashboard.tsx`
> **الاختبارات:** C120–C138
> **قرار مالك المشروع:** رمز الطوارئ `19871987` يبقى (خيار A) + توثيق + تسجيل استخدام

---

## 1. الوضع الحالي

### س: كيف يعمل `handleRecovery`؟
1. يتحقق من طول الرمز (8 أرقام).
2. يقرأ `recoverySalt` و `recoveryHash`.
3. يحسب SHA-256.
4. يقارن.
5. **عند النجاح: ينتقل إلى `newPin` مباشرة دون حذف `recoveryHash`/`recoverySalt`.**

**الخلل:** رمز الاسترداد يبقى صالحاً بعد الاستخدام (ثغرة أمنية).

### س: رمز الطوارئ `19871987`؟
- مسار تجاوز ثابت (backdoor مقصود).
- **يُقبل حتى بعد استهلاك رمز الاسترداد.**
- لم يُسجَّل تاريخ استخدامه.

---

## 2. القرارات المعتمدة

### س: كيف نُبطل رمز الاسترداد؟
**ج:** في `handleRecovery`، **فور نجاح التحقق**:
1. حذف `KEYS.recoveryHash`.
2. حذف `KEYS.recoverySalt`.
3. **التحقق** من اختفائهما.
4. **ثم** الانتقال إلى `newPin`.

**إذا فشل الحذف:** لا ننتقل إلى `newPin`.

**ملاحظة:** لا نحذف `pinHash`/`pinSalt` — PIN القديم يبقى صالحاً حتى حفظ الجديد.

### س: رمز الطوارئ `19871987`؟
**ج:** قرار مالك المشروع: **يبقى (خيار A)**.

**المبررات:**
- fallback أخير إذا فقد ولي الأمر PIN + الاسترداد.
- مضمّن في العميل = ليس سراً أمنياً، توثيقه أفضل من ادعاء الحماية.

**الإضافات المعتمدة:**
- وصفه في الواجهة كـ "رمز طوارئ" لا "رمز سري".
- **تسجيل كل استخدام** في `soroban_emergency_used_at` (ISO 8601 UTC).
- عرض آخر استخدام في `GuardianDashboard`.

### س: قفل التزامن؟
**ج:** `useRef` كقفل متزامن حول `handleRecovery` — لمنع النقر المزدوج أو إدخال Enter متزامن.

---

## 3. المفتاح الجديد `soroban_emergency_used_at`

| الخاصية | المواصفة |
|---|---|
| الاسم | `soroban_emergency_used_at` |
| النوع | String |
| التنسيق | ISO 8601 UTC (`2026-11-16T19:31:00.000Z`) |
| المعنى | وقت **آخر** استخدام لرمز الطوارئ |
| الكتابة | `LocalPinGuard` عند قبول رمز الطوارئ |
| القراءة | `GuardianDashboard` |
| البادئة | **لا بادئة Local/Cloud** (سجل محلي خاص ببوابة PIN) |
| المسح | لا يوجد زر مسح (P3-Future) |

**ملاحظة مهمة:** المفتاح يحفظ **آخر** استخدام فقط (timestamp واحد)، وليس سجلاً تاريخياً.

### س: ماذا يعرض GuardianDashboard؟

| حالة المفتاح | ما يظهر |
|---|---|
| لا قيمة | "لم يُسجل استخدام لرمز الطوارئ" |
| Timestamp صالح | "آخر استخدام: [التاريخ والوقت]" |
| قيمة تالفة | "تعذر قراءة سجل الاستخدام" |

**نبرة العرض:** تنبيه للمراجعة، **ليس اتهاماً**. النص لا يقول "اختراق"، لأنه timestamp محلي قابل للتعديل/الحذف.

### س: ماذا لو فشلت كتابة الـ timestamp؟
**ج:** مسار الطوارئ يبقى متاحاً (وظيفة الاسترداد لا تُعطَّل)، مع تحذير: "لم يُسجّل الاستخدام".

## 4. القرارات النهائية (D8–D16)

| # | القرار |
|---|---|
| D8 | رمز الاسترداد العشوائي أحادي الاستخدام |
| D9 | إبطال `recoveryHash` + `recoverySalt` قبل `newPin` |
| D10 | لا حالة استرداد معلّقة بعد إغلاق التطبيق |
| D11 | الرمز الثابت `19871987` يبقى (backdoor مقصود موثق) |
| D12 | تسجيل `soroban_emergency_used_at` عند كل استخدام |
| D13 | GuardianDashboard يعرض آخر timestamp |
| D14 | P2-06b Commit مستقل (خارج نطاق P2-06) |
| D15 | لا يُعاد إحياء `recoveryToken` عند فشل حفظ PIN |
| D16 | زر مسح سجل الطوارئ = P3-Future |

## 5. الاختبارات C120–C138

| # | السيناريو | النتيجة |
|---|---|---|
| C120 | رمز صحيح | حذف hash+ salt قبل `newPin` |
| C121 | إعادة استخدام الرمز | رفض |
| C122 | رمز خاطئ | الاحتفاظ |
| C123 | طول غير صحيح | رفض دون حذف |
| C124 | hash أو salt مفقود | رفض الرمز |
| C125 | إغلاق بعد الاستهلاك وقبل PIN | الرمز غير صالح، PIN القديم باقٍ |
| C126 | حفظ PIN بنجاح | إنشاء hash + salt جديدين |
| C127 | PIN الجديد ≠ التأكيد | لا إعادة تفعيل |
| C128 | فشل حذف بيانات الاسترداد | لا انتقال إلى `newPin` |
| C129 | نقر مزدوج | قبول عملية واحدة |
| C130 | رمز الطوارئ | قبول |
| C131 | رمز الطوارئ بنجاح | كتابة timestamp |
| C132 | استخدام متكرر | تحديث timestamp |
| C133 | فشل كتابة timestamp | لا ادعاء بالتسجيل + تحذير |
| C134 | Dashboard مع timestamp | عرض |
| C135 | Dashboard بدون timestamp | "لم يُسجل" |
| C136 | timestamp تالف | "سجل غير صالح" |
| C137 | رمز استرداد بعد طوارئ | سلوك مستقل (لا يتغير) |
| C138 | Chaos: فشل تخزين | لا ادعاء نجاح |

## 6. خارج النطاق

- إزالة `19871987`.
- جعله فريداً لكل جهاز.
- الادعاء بأنه سر.
- سجل تاريخي متعدد الأحداث (فقط آخر استخدام).
- حالة استرداد معلّقة.
- حذف PIN القديم عند التحقق فقط.
- زر مسح سجل الاستخدام (P3-Future).
- حذف تقدم الطفل.
